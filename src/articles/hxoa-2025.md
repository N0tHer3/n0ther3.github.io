## 0x02 SSRF 漏洞

打开小熊猫插件，可以直接看到一个 url 参数。一般简单的 SSRF 漏洞，url 如果没有进行过滤，很容易导致 SSRF：

![页面中的 url 参数](./images/hxoa-4.png)

由 app.js 可知，`var API_BASE = '/api'`，所以我们需要携带 API_BASE 进行访问接口：

```text
http://10.239.12.190:8000/api/imgproxy.php?url=http://www.baidu.com
```

![imgproxy 接口成功访问外链](./images/hxoa-5.png)

测试能访问外链就行。当然你要是知道目标的内网地址，也可以访问内网服务。

## 0x03 水平越权获取敏感信息

接着我们查看个人中心：

![个人中心的 UUID](./images/hxoa-6.png)

可以发现用户的个人中心有一个 UUID 值，抓个包看看：

![抓包：请求直接携带 uuid 查询](./images/hxoa-7.png)

可以发现请求包是直接携带 uuid 进行查询的，那如果我们能获取到别人的 uuid 是不是就可以获取到别人的信息了？继续查找接口：

![search.php 接口](./images/hxoa-8.png)

可以发现这边有一个 search.php。为什么要找到这个接口？因为博主之前在挖漏洞的时候，有些用户的 uuid 不一定只有在用户的个人中心里面才有，有时候你要搜索一个用户，返回包就会出现：

![搜索返回所有用户的 uuid](./images/hxoa-9.png)

于是也是不出所料找到了所有用户的 uuid。于是通过替换 uuid 就可以查询其他人的敏感信息：

![替换 uuid 查询他人敏感信息](./images/hxoa-10.png)

## 0x04 任意文件读取

接口中有一个文件预览的接口，它是通过 path 参数，不过滤的话就会引发任意文件读取漏洞：

![文件预览接口的 path 参数](./images/hxoa-11.png)

```text
http://10.239.12.190:8000/api/fileview.php?path=/api/config.php
```

![读取 /api/config.php 源码](./images/hxoa-12.png)
